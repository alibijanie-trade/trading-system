## بخش ۱ — اصول بنیادی (Locked)

این اصول **غیرقابل تغییر** هستند. اگر تغییر لازم شد، باید با تأیید صریح کاربر **و** ثبت در `DECISIONS_LOG` انجام شود.

### اصل ۱ — حافظه پروژه بیرونی است، نه در ذهن Claude

Claude در هر چت جدید **خاطره‌ای از چت‌های قبلی ندارد**. تمام دانش پروژه باید در **اسناد** باشد.

> پیامد: اگر چیزی در اسناد نیست، **وجود نخواهد داشت** برای Claude بعدی.

### اصل ۲ — هیچ‌چیز سرسری گرفته نمی‌شود

هر تصمیم، Bug، تغییر، الگو، یا داستان باید:
- در محل **متناسب** (یکی از ۱۲ سند) ثبت شود
- با **چرا** + **چه چیز** + **چه زمان** مستند شود
- **قابل جستجو** باشد (نه پراکنده)

### اصل ۳ — اسناد افزوده می‌شوند، نه پاک

تغییر در اسناد فقط با ۳ روش مجاز است:
1. ✏️ **افزودن** بخش جدید
2. ✅ **اصلاح** با نشان دادن `❌ قبل → ✅ بعد`
3. 🔄 **به‌روزرسانی state** (status، version، DONE list)

> ⛔ **هرگز حذف نشود.** اگر چیزی منسوخ شد، با علامت `[منسوخ — vX.Y]` نگه داشته شود.

### اصل ۴ — حرفه‌ای‌گری در همه چیز

**معیار حرفه‌ای بودن:**
- یک برنامه‌نویس دیگر بتواند ظرف **یک روز کاری** پروژه را درک کند
- یک Claude جدید بتواند ظرف **۵ دقیقه** بداند پروژه کجاست و چه باید بکند
- هیچ "دانش قبیله‌ای" نباشد — همه چیز مستند

### اصل ۵ — ابهام تحمل نمی‌شود

اگر Claude در هر مرحله شک کرد، **اجباری است که بپرسد** نه فرض کند. این یک قانون امنیتی است.

### اصل ۶ — Reusability از روز اول

پروژه از روز اول طوری طراحی می‌شود که **اسکلت آن قابل بازاستفاده** برای پروژه‌های آینده باشد. domain-specific و reusable از همان ابتدا تفکیک شوند.

## بخش ۳ — قوانین به‌روزرسانی سند جامع

### قانون G1 — versioning

هر تغییر در سند جامع → **افزایش minor version** (v2.7 → v2.8). تغییرات بنیادی (یعنی تغییر در اصول بنیادی این سند راهبردی) → **major version** (v2.x → v3.0).

### قانون G2 — Change Log اجباری

هر نسخه جدید سند جامع باید **در ابتدا** بخش "تغییرات این نسخه" داشته باشد:

```markdown
## تغییرات v2.X (نسبت به v2.{X-1})
### افزوده شد
- بخش ...
### اصلاح شد (❌ → ✅)
- بخش ...: قبلاً X بود، حالا Y به دلیل ...
### قوانین جدید
- #۲۳: ...
### Bug ثبت شد
- #۴۶: ...
```

### قانون G3 — No-Deletion

اگر بخشی منسوخ شد:
```markdown
## ۸.۵.۱ — [منسوخ — v2.7] فلان روش قدیمی

> ⚠️ از v2.7 منسوخ شد. روش جدید در بخش ۸.۵.۲ مستند شده. 
> دلیل منسوخ شدن: ...

[محتوای قدیمی برای reference تاریخی...]
```

### قانون G4 — Cross-Reference

هر بخش جدید سند جامع که به مفهومی اشاره می‌کند که در سند دیگری مستند است، باید **link یا شماره بخش** بدهد:

> برای محدودیت context Claude، بخش ۱۶.۱ سند جامع را ببینید، و برای checklist عملیاتی، `CLAUDE_CHECKLIST.md` را مراجعه کنید.

### قانون G5 — Atomicity

به‌روزرسانی سند جامع باید **اتمیک** باشد: همه بخش‌های مرتبط در یک نسخه به‌روز شوند. اگر یک قانون جدید اضافه شد و اصلاح بخش‌های مرتبط در سند جامع، CHAT_LOG، و PROJECT_GOVERNANCE فراموش شد، **همان لحظه فاجعه‌بار است**.

## بخش ۵ — Protocol پایان چت

این Protocol در ۲ سناریو فعال می‌شود:
- 🔵 **سناریوی برنامه‌ریزی‌شده:** کاربر می‌گوید "بسته شود" یا "پایان چت"
- 🟡 **سناریوی هشدار:** context چت > ۷۰٪ یا کیفیت در حال افت

### مرحله ۱ — پیشنهاد توقف (Claude initiate در سناریو ۲)

Claude بگوید:
> "حافظه چت در حال نزدیک شدن به اشباع است. پیشنهاد می‌کنم پروتکل پایان چت را شروع کنیم تا کیفیت اسناد نهایی حفظ شود."

### مرحله ۲ — جمع‌بندی کارهای انجام‌شده

Claude لیست می‌کند:
- ✅ اسکریپت‌های تولیدشده
- ✅ Bug های رفع‌شده
- ✅ تصمیمات گرفته‌شده
- ✅ Task های Done شده در Backlog
- ⏳ کارهای ناتمام

### مرحله ۳ — به‌روزرسانی اسناد (ترتیب اجباری)

```
۱. CHAT_LOG.md         — افزودن بخش این چت
۲. TASK_BACKLOG.md     — به‌روز کردن وضعیت
۳. DECISIONS_LOG.md    — اگر تصمیم جدید
۴. TROUBLESHOOTING.md  — اگر Bug جدید
۵. GLOSSARY.md         — اگر اصطلاح جدید
۶. STYLE_GUIDE.md      — اگر pattern جدید
۷. SESSION_STATUS.md   — وضعیت پایان چت
۸. PROJECT_CONTEXT.md  — به‌روز با مراجع جدید
۹. CHANGELOG.md        — اگر version bump
۱۰. سند جامع         — اصلی‌ترین — با ادغام PENDING_FOR_NEXT_VERSION.md
۱۰.۵. PENDING_FOR_NEXT_VERSION.md 🆕 v2.10 — پاک‌سازی بخش‌های ۱-۶ (پروتکل ۷.۳ خود فایل)
۱۱. README.md          — اگر تغییر بنیادی
۱۲. zip نهایی         — همه فایل‌ها
```

### مرحله ۴ — تعیین نام چت (در پایان، نه ابتدا)

طبق سند جامع بخش ۱۳.۶ (با اصلاحیه v2.7):

```
TRADING-phase{N}-part{NN}-{topic-slug}
```

- `{N}`: تک‌رقم 0-based — `phase0`، `phase1`، ...
- `{NN}`: دو رقم — `part01`، `part02`، ...
- `{topic-slug}`: بر اساس **موضوعات واقعی** انجام‌شده

### مرحله ۵ — پیشنهاد نام چت بعد

Claude بر اساس Tier فعلی Backlog و گام منطقی بعدی، یک نام پیشنهادی می‌دهد.

### مرحله ۶ — ارائه zip + پیام پایانی

Claude:
1. zip را با همه اسناد به‌روز می‌سازد
2. لیست کامل تغییرات را اعلام می‌کند
3. نام چت فعلی + پیشنهاد نام چت بعد

## بخش ۱۱ — Anti-Patterns ممنوع

اینها **هرگز** نباید رخ دهند. اگر Claude متوجه شد، باید فوری توقف کند.

### Anti-Pattern A1 — Hex Hardcoded در CSS/JSX
```jsx
// ❌ ممنوع
<div style={{ color: "#F0B90B" }}>

// ✅ صحیح
<div style={{ color: "var(--color-primary)" }}>
```

### Anti-Pattern A2 — Query مستقیم بیرون از Repository
```python
# ❌ ممنوع
async def some_endpoint(db):
    result = await db.execute(select(User)...)

# ✅ صحیح
async def some_endpoint(repo: UserRepository):
    result = await repo.get_active_users()
```

### Anti-Pattern A3 — تست با Swagger UI به جای کد
```bash
# ❌ ممنوع — رفتن به /docs و کلیک
# ✅ صحیح — اسکریپت httpx
python scripts/Nb_test_endpoint.py
```

### Anti-Pattern A4 — حذف از سند
```markdown
# ❌ ممنوع — حذف کامل بخش
# ✅ صحیح — علامت‌گذاری منسوخ
## ۸.۵ — [منسوخ — v2.X] روش قدیمی
```

### Anti-Pattern A5 — اسکریپت غیر idempotent
```python
# ❌ ممنوع
file.write_text(NEW_CONTENT)  # هر بار overwrite، بدون چک

# ✅ صحیح
if file.read_text() != NEW_CONTENT:
    file.write_text(NEW_CONTENT)
```

### Anti-Pattern A6 — تولید اسکریپت بدون تست همراه
```
# ❌ ممنوع — فقط 33_feature.py
# ✅ صحیح — 33_feature.py + 33b_test_feature.py
```

### Anti-Pattern A7 — کد منسوخ بدون علامت
```jsx
// ❌ ممنوع
function oldComponent() { ... }  // استفاده نمی‌شود

// ✅ صحیح
/** @deprecated از v2.7 — به‌جای آن از NewComponent استفاده کنید. */
function oldComponent() { ... }
```

### Anti-Pattern A8 — فرض بدون پرسش
```
# ❌ ممنوع
"کاربر احتمالاً می‌خواهد X..." [و انجام X بدون تأیید]

# ✅ صحیح
"می‌خواهید X انجام دهم یا Y؟"
```

### Anti-Pattern A9 — هر تنظیم در inline (Magic Numbers)
```jsx
// ❌ ممنوع
<div style={{ padding: 24, maxWidth: 900 }}>

// ✅ بهتر — اگر تکرار شد
// (در فاز ۰ این هنوز قابل قبول است، در فاز ۲+ به constants)
```

### Anti-Pattern A10 — به‌روزرسانی غیر-اتمیک

اگر یک قانون جدید اضافه شد ولی فقط در سند جامع آمد و در CHAT_LOG/PROJECT_GOVERNANCE نیامد → **فاجعه آینده**.

### Anti-Pattern A11 — نادیده گرفتن PENDING-EOC (🆕 v2.10) ⭐⭐⭐

اگر در چت یک [PENDING-EOC] کشف شد ولی **همان لحظه** در `docs/PENDING_FOR_NEXT_VERSION.md` ثبت نشد → در پایان چت گم می‌شود (تجربه چت ۷ → M23).

```
# ❌ ممنوع
"این مورد را در پایان چت اضافه می‌کنم..."  → فراموش می‌شود

# ✅ صحیح (قانون #۶۰)
"📝 [PENDING-EOC کشف شد] — اکنون با MCP در PENDING_FOR_NEXT_VERSION.md ثبت می‌کنم"
[edit_file فوری]
[read-back verify]
"✅ ثبت شد. ادامه..."
```

این **مهم‌ترین** Anti-Pattern چت‌های پایان‌فاز است.

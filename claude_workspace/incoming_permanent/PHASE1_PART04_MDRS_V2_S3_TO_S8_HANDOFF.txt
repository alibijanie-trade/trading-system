## CRITICAL LESSONS APPLIED IN THIS CHAT (DO NOT FORGET)

These were the user catches that emerged as M-lesson candidates. The next chat MUST honor them from boot:

### M93 — Triple-Rule Atomic Boundary
Stage-end commits must include SESSION_STATUS.md + CHAT_LOG.md + (optionally) PROJECT_MANIFEST.md in the SAME atomic commit, before push. Never leave modifications uncommitted at chat-end. Discovered via Z3.11 (chat 11.0.ج SESSION_STATUS was modified but not committed).

### M96 — Z-ID Permanence
Z-IDs (Z3.X format) live only in the gitignored tracker file (MDRS_V2_PENDING_DRAFT.md). Permanent docs must NEVER reference Z-IDs. Use M-candidate IDs, Rule numbers, Decision numbers, or generic descriptive language. Discovered in S2.2 design via user Q4 catch.

### M97 — CMD Em-Dash + Redirect Catastrophe
Multi-byte Unicode characters (em-dash, en-dash, arrows, smart quotes) in CMD commit messages can break quote-tracking and trigger redirect side effects. Evidence: stray file `M` was created in project root during S2.2 attempt 1.

### M98 — Review Scope Closure
Reviews must be temporally closed. Forward references to upcoming work (TBD hashes, [upcoming], unbounded placeholders) are anti-pattern. Discovered via user Q3+Q4+Catch trio in S2.3 design.

### M99 — Git Commit -F Flag Standard
For long commit messages (3+ -m flags OR 500+ chars), ALWAYS use git commit -F with a temp file in claude_workspace/. Inline -m chains have 100% failure rate for long commits in S2. The -F flag eliminates all CMD quoting issues.

### M100 — Hidden-Checklist Completion
Pre-action checklists (PRE_ADD_CHECKLIST §3, CLAUDE_CHECKLIST steps) must be visible in chat surface. Mental/implicit completion is invisible to partner (user or future audit). Each check needs Yes/No + brief reasoning. Discovered in S2.4 design via user Q4 catch.

### Commit Pattern (M99 + M95 + M97 applied)

For any commit with body content (most MDRS v2 commits):

1. Claude writes message to claude_workspace/commit_msg_{stage}.txt via Filesystem:write_file
2. User executes:
   ```
   git add {files}
   git commit -F claude_workspace/commit_msg_{stage}.txt
   del claude_workspace\commit_msg_{stage}.txt
   ```
3. Always ASCII-only in commit messages, even though `-F` reduces metachar risk

### Pre-Add Checklist Pattern (M100)

When the user proposes adding any new artifact (T1/T2 doc, script, etc.), Claude must:
1. Output the explicit 10-check pre-add checklist from docs/PRE_ADD_CHECKLIST.md
2. Mark each check with Yes/No + brief reasoning
3. Show explicit Decision (Proceed, Trigger Review, or Defer/Reject)
4. Only then proceed to design or implementation

### Review-Then-Approve Pattern

For substantive document creation in S3:
1. Claude writes preview in chat (full document body)
2. User reviews and provides refinements (often discovering new lessons)
3. Claude integrates refinements + writes file
4. Read-back diff verify
5. Stage + commit (with -F) + push

### Atomic Stage-end Pattern (M93)

Last sub-commit of each stage:
- SESSION_STATUS.md full refactor (not append)
- CHAT_LOG.md new sub-section append
- PROJECT_MANIFEST.md D2 re-run if file changes warrant

- Push immediately after commit
